# MC01-RC RS485 实板测试报告

## 1. 测试结论

测试日期：2026-09-07

两路 RS485 在 2 Mbaud、8N1 条件下完成外部双向 Echo 测试。DMA 半满、DMA 全满和 UART 接收超时三种接收入队路径均被实际触发，6 个 Echo 用例、12 次物理方向传输全部通过。

- 通过位图：`0x3F`
- UART 错误：两路均为 0
- 软件 RX 队列丢包：两路均为 0
- 最后一次接收长度：128 字节

## 2. 测试环境

- 目标器件：STM32C5A3RGT6
- 调试器：DAPLink，UID `D641959C00B43ECC`
- 下载与调试工具：项目 `.venv` 中的 pyOCD
- 构建预设：`debug_GCC_STM32C5A3RGT6`

- 物理连接：RS485-1 与 RS485-2 的 A、B 对应互连

## 3. 硬件接口与方向控制

| 端口 | UART | TX | RX | DE | 接插件 |
| --- | --- | --- | --- | --- | --- |
| RS485-1 | UART5 | PC12 | PD2 | PC8 | P5 |
| RS485-2 | USART2 | PA2 | PA3 | PA1 | P4 |

两路收发器的 `/RE` 与 `DE` 并接，低电平为接收、高电平为发送。固件启用 STM32 USART RS485 Driver Enable 模式，DE 高有效；发送起止时刻由 UART 硬件自动控制，没有使用软件 GPIO 切换方向。

测试结束后读取到两路 UART：

- `CR3 = 0x00006141`，`DEM=1`、`DEP=0`，确认硬件 DE 已启用且高有效。
- `BRR = 0x00000048`，与当前 UART 内核时钟下的 2 Mbaud 配置一致。

## 4. 不定长接收实现

每路 RS485 使用：

- 128 字节循环 RX DMA 缓冲区
- 512 字节软件字节环形队列
- 150 bit 接收超时，2 Mbaud 下约为 75 us

接收事件处理：

1. DMA Half 回调将 DMA 缓冲区前半段的新增字节入队。
2. DMA Full 回调将后半段的新增字节入队并处理 DMA 位置回绕。
3. UART RTO 回调将不足半缓冲区的尾段新增字节入队。
4. 三种回调共享上次 DMA 位置，只搬运新增区间，避免重复入队。
5. 用户在主循环中通过 `bsp_rs485_rx_pending()` 和 `bsp_rs485_read()` 非阻塞读取任意长度字节流。

## 5. 用户侧 API

| API | 用途 |
| --- | --- |
| `bsp_rs485_configure()` | 设置波特率、硬件 DE 和超时，并启动持续循环 RX DMA |
| `bsp_rs485_transmit()` | 使用 TX DMA 异步发送，方向由 UART 硬件控制 |
| `bsp_rs485_rx_pending()` | 查询软件 RX 队列中的可读字节数 |
| `bsp_rs485_read()` | 从软件 RX 队列读取不定长数据 |
| `bsp_rs485_get_status()` | 查询发送状态、事件计数、错误和丢包 |
| `bsp_rs485_abort()` | 终止当前端口收发 |

`bsp_rs485_transmit()` 是异步接口，发送缓冲区必须保持有效，直到状态中的 `tx_busy` 变为 false。

## 6. 外部 Echo 测试方法

每个用例均执行“发起端发送 → 对端从软件队列读取并校验 → 对端原样回送 → 发起端读取并校验”。测试报文使用递增规律数据，不仅比较长度，也逐字节校验内容。

| 用例 | 发起端 | 长度 | 主要覆盖路径 | 结果 |
| --- | --- | ---: | --- | --- |
| 1 | RS485-1 | 17 字节 | RTO 尾段入队 | 通过 |
| 2 | RS485-2 | 17 字节 | RTO 尾段入队 | 通过 |
| 3 | RS485-1 | 64 字节 | DMA Half 入队 | 通过 |
| 4 | RS485-2 | 64 字节 | DMA Half 入队 | 通过 |
| 5 | RS485-1 | 128 字节 | DMA Full 与回绕 | 通过 |
| 6 | RS485-2 | 128 字节 | DMA Full 与回绕 | 通过 |

## 8. 问题定位记录

早期定长中断接收测试中，UART5 在 2 Mbaud 下出现 `ORE` 接收溢出。启用两路 FIFO，并改为循环 DMA 搭配 Half、Full、RTO 增量入队后，实板复测未再出现 UART 错误或数据丢失。

pyOCD 下载时提示 DFP 缺少 Flash programming debug sequence，并自动回退到 FLM；下载成功，不影响本次测试结果。
